# Agent Note: OptMem 隔离边界是工作区

Status: implemented

## 问题

同一个项目的 worktree 常用于并行分支工作，DSH profile 也只是会话配置的一种选择。把项目记忆按检出目录或 profile 切开，会让经用户批准的项目决策在这些入口之间反复丢失。独立仓库和普通目录仍不应串读。

## 决策

[OptMem 的独立 SQLite 库](2026-11-25-optmem-dsh-workspace-store.md) 在每个 DSH home 使用一个文件，由带类型的工作区键限定读写。Git 使用最近工作树的真实 Git 公共目录；普通目录使用会话当前目录的真实路径。

写入确认显示当前检出目录和共享 Git 公共目录。即使两个检出终点能读同一份记录，等待确认时切换目录也不能让一张旧确认卡授权新目标。批准后仍核对原会话和工作区。

## 曾考虑的替代方案

**用远程地址、仓库名或最近的共同父目录。** 相同远程的独立 clone 可以服务不同项目或用途；相邻目录也未必属于同一仓库。只跟随本机 Git 建立的公共目录关系，不让这些启发式意外扩展读写范围。

**按 profile 或检出目录分库。** 这会把同一个工作区的记忆按会话配置或分支检出切开。持久记忆以工作区为边界，不以使用它的 profile 或分支为边界。

## 后果

同一 DSH home 内不能再用 profile 隔离同一个工作区的记忆；真正需要独立副本时使用独立工作区或 DSH home。不同 Git 仓库和非 Git 目录仍独立。移动 Git 公共目录或普通目录会改变其路径身份。

隔离测试核对 main/linked worktree 共用、独立仓库和普通目录不串读、同 home 跨 profile 可见，以及切换确认目标时不写入。
