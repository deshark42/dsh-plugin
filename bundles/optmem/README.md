# OptMem 工作区记忆

OptMem 是 DeepSeek Harness 的 Host-only 插件。助手可以在当前工作区查找长期记忆，或在你确认后保存一条。插件使用 Node 自带的 SQLite，运行时不依赖外部命令，也不发额外的模型请求。

## 安装

1. 需要 DSH `0.2.3-alpha.2` 或包版本范围内的新版。在 DSH 的 **插件 → 添加插件** 填入本目录的绝对路径，再启用 **OptMem 工作区记忆**。
2. 在项目的主会话说「请记住：这个项目的插件测试在插件目录执行」。核对确认卡上的工作区和原文，选「保存到 OptMem」后点「提交」。再试「用 memo 搜一下关于插件测试的记忆」。

## 模型工具 `memo`

- `search`，传 `query`：按不区分大小写的字面子串搜索，返回最新匹配的 ID、摘录和时间。`truncated` 标记个别摘录省略正文，`hasMore` 表示还有匹配，可用更具体的关键词缩小范围。查询最多 256 个 UTF-8 字节。
- `get`，传 `id`：取该条记忆的原文和时间。ID 必须来自同一工作区。
- `note`，传 `text`：提议保存一条非空单行记忆，最多 1200 个 UTF-8 字节，不允许首尾空白、控制字符或不可见格式字符。确认卡显示工作区、数据库与将原样保存的文本；对 Git 工作区也显示所有 worktree 共享的 Git 公共目录。拒绝、跳过、关闭、填写自由文本、超时或目标变更都不写入；90 秒内未提交就结束等待。要改正文，请回到聊天里说明。

在 Code Mode 中也使用同一个工具：

```js
inspect(await tools.memo({ action: 'search', query: '测试' }))
```

插件不自动把库带入新会话，不自动总结或写入。主动检索的文本与提议保存的内容都可能出现在会话历史；拒绝只阻止写入记忆库。请勿提交凭据或不想留在会话里的内容。子代理不能主动调用 `memo`，但可能继承父会话已有的历史。

## 数据与配置

数据库位于 `$DSH_HOME/data/optmem/memory.sqlite`（默认 `$DSH_HOME` 为 `~/.dsh`）。同一 DSH home 内，`memo` 按工作区隔离记录，不按 profile 分库；使用同一工作区的不同 profile 可以互相查到已保存的记忆。不同 DSH home 各自保存。停用插件不会删除已保存的记忆。

- **Git 工作区**：从会话目录向上找到最近的 Git 工作树，用其 Git 公共目录的真实路径识别仓库。主工作树与所有 linked worktree 共享；不同 clone（即使远程地址相同）和独立的嵌套仓库不共享。移动 linked worktree 且 Git 关联保持不变时，仍使用原库；移动 Git 公共目录则换工作区。
- **非 Git 工作区**：用会话当前目录的真实路径识别。不同目录各自独立；符号链接指向同一个真实目录时使用同一份记录。移动或改名后按新路径识别。

模型不能指定库或工作区。数据库路径不跟随符号链接；如果 Git 元数据或数据库路径不可用，不回退到其他工作区。

唯一的插件配置项是 `searchLimit`，默认 6，支持 1–12。可在 DSH 配置中覆盖 `optmem` 行：

```yaml
- id: optmem
  name: '@local/dsh-optmem'
  config:
    searchLimit: 8
```

在插件目录运行 `npm test`。设有 `DSH_INSTALL_DIR` 和 `DSH_NODE_EXECUTABLE` 时，还会用当前安装的 DSH 执行宿主测试；测试只读写隔离夹具，不用真实 profile 或记忆库。
